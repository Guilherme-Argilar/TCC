\subsection{Banco de Dados Utilizado}
  Para o desenvolvimento do projeto, optamos pelo SQLite como sistema de gerenciamento de banco de dados. Essa escolha foi estratégica, considerando dois fatores críticos: a necessidade de operação \textit{offline} e as limitações de \textit{hardware} dos totens. O SQLite, sendo extremamente leve e eficiente, consome recursos mínimos de memória e processamento, ideal para dispositivos com capacidade limitada.

  O banco foi estruturado para gerenciar informações de feiras e eventos de forma otimizada. A arquitetura prioriza consultas rápidas e diretas, organizando dados de visitantes (\textit{leads}), expositores, produtos e categorias para minimizar operações complexas.

  A tabela \textit{Lead} constitui o núcleo do sistema, armazenando dados completos dos visitantes --- informações pessoais, profissionais e suas interações com o totem. Cada \textit{lead} é vinculado às categorias de interesse e expositores pesquisados, criando um perfil detalhado de comportamento.

  Os expositores são organizados com suporte a múltiplas categorias, incluindo o atributo ``Predio'' --- adição fundamental para o caso de uso do Tecnopuc, permitindo localização física precisa dentro do parque tecnológico. O sistema de categorização hierárquico (categorias e subcategorias) foi implementado priorizando \textit{performance}, com índices estratégicos para acelerar as buscas mais frequentes.

  A escolha do SQLite provou-se acertada para o contexto do projeto. Sua natureza \textit{serverless} elimina \textit{overhead} de comunicação, seu \textit{footprint} mínimo preserva recursos do sistema, e sua capacidade de operar em memória garante respostas rápidas. A estrutura foi projetada evitando junções múltiplas e subconsultas complexas, garantindo fluidez mesmo em \textit{hardware} básico. Essa combinação de banco leve com modelagem eficiente demonstrou que é possível criar sistemas robustos operando sob severas restrições de \textit{hardware}, proporcionando experiência responsiva aos usuários das feiras.

\subsection{Arquitetura Utilizada}
  O projeto Totem Interativo foi desenvolvido utilizando uma arquitetura cliente-servidor moderna, que estabelece uma clara separação entre \textit{frontend} e \textit{backend}. Essa abordagem otimizou o desenvolvimento paralelo das camadas, aumentou a manutenibilidade do sistema e conferiu flexibilidade para futuras expansões.

\subsubsection{Frontend}
  A arquitetura do \textit{frontend} foi concebida para oferecer uma aplicação interativa com renderização 3D. A estrutura modular facilitou tanto o desenvolvimento quanto a manutenção.

  Os componentes da interface foram organizados em grupos lógicos:
\begin{itemize}
    \item \textit{dropdown}: para menus de seleção e filtros;
    \item \textit{map}: responsável pela renderização e interação com o mapa 3D;
    \item \textit{searchbar}: para funcionalidades de busca;
    \item \textit{sidebar}: para navegação e exibição de informações contextuais.
\end{itemize}

  A comunicação com o \textit{backend} foi centralizada na camada de \textit{services}, atuando como um ponto único de integração com as APIs. O gerenciamento de estados globais é feito via \textit{contexts}, e lógicas reutilizáveis, como o \textit{logout} automático por inatividade, foram isoladas em \textit{hooks}.

  Recursos estáticos essenciais para o mapa 3D foram estrategicamente organizados:
\begin{itemize}
    \item \textit{models}: arquivos de geometria dos edifícios;
    \item \textit{textures}: materiais visuais aplicados aos modelos;
    \item \textit{fonts}: tipografias personalizadas para a identidade visual;
    \item \textit{assets}: recursos gráficos gerais da aplicação.
\end{itemize}

  As rotas da aplicação são diferenciadas conforme o perfil do usuário: visitantes acessam a interface principal do totem, enquanto administradores dispõem de páginas específicas para importação de dados (\textit{admin-import}) e exportação de relatórios (\textit{admin}). A funcionalidade de \textit{QR Code} possui um módulo próprio com componentes dedicados.

\subsubsection{Backend}
  A arquitetura do \textit{backend} adotou padrões de desenvolvimento em camadas, garantindo uma clara segregação de responsabilidades e facilitando os processos de teste e manutenção.

  A estrutura de camadas implementada é composta por:
\begin{itemize}
    \item \textit{Controllers}: atuam como ponto de entrada para as requisições HTTP;
    \item \textit{Services}: encapsulam toda a lógica de negócio da aplicação;
    \item \textit{DTOs}: definem os contratos de dados para entrada e saída;
    \item \textit{Entities}: representam as estruturas do banco de dados;
    \item \textit{Modules}: agrupam logicamente as funcionalidades.
\end{itemize}

  Aspectos transversais foram concentrados no diretório \textit{common}:
\begin{itemize}
    \item \textit{Guards}: para proteção de rotas administrativas;
    \item \textit{Filters}: para tratamento padronizado de erros;
    \item \textit{Mapper}: para transformações entre diferentes representações de dados.
\end{itemize}

  O armazenamento local foi estruturado no diretório \textit{database}, contendo o arquivo principal SQLite.

  O fluxo de dados segue um padrão consistente: as requisições chegam aos \textit{controllers}, são validadas pelos \textit{DTOs}, processadas pelos \textit{services} (que interagem com as \textit{entities}), e então retornam respostas estruturadas. As operações administrativas incluem \textit{endpoints} especializados para importação em massa via CSV e exportação de dados agregados.

  A estrutura de testes replica a organização principal, com diretórios específicos para \textit{controllers} e \textit{services}, assegurando uma cobertura adequada das funcionalidades críticas.

\subsection{Tecnologias Utilizadas}
  Nesta seção serão apresentadas as principais tecnologias empregadas no desenvolvimento do projeto Totem Interativo, destacando suas contribuições para o sucesso da implementação.

\begin{itemize}
    \item \textbf{React:} Biblioteca JavaScript de código aberto para construção de interfaces de usuário reativas e componentes reutilizáveis, fundamental para criar a interface interativa do totem com atualizações dinâmicas.
    \item \textbf{Three.js:} Biblioteca JavaScript para renderização 3D no navegador, responsável pela criação e manipulação do mapa tridimensional interativo, permitindo visualização imersiva dos espaços e interações com elementos 3D.
    \item \textbf{Next.js:} \textit{Framework} React para desenvolvimento \textit{web} com renderização híbrida e otimizações automáticas de \textit{performance}, garantindo resposta rápida mesmo em \textit{hardware} limitado.
    \item \textbf{Node.js:} Ambiente de execução JavaScript \textit{server-side} com natureza assíncrona e eficiência no gerenciamento de I/O, ideal para múltiplas requisições simultâneas.
    \item \textbf{NestJS:} \textit{Framework} progressivo para Node.js que permite construção de aplicativos escaláveis com arquitetura modular e suporte nativo para TypeScript.
    \item \textbf{TypeScript:} \textit{Superset} do JavaScript que adiciona tipagem estática opcional, reduzindo \textit{bugs} em tempo de desenvolvimento e facilitando manutenção do código.
    \item \textbf{Swagger:} Ferramenta para documentação e testes interativos de APIs RESTful, integrada ao NestJS para gerar documentação automática dos \textit{endpoints}.
    \item \textbf{SQLite:} Sistema de banco de dados relacional \textit{serverless} e baseado em arquivo único, escolhido por sua leveza e capacidade de operar sem dependências externas em ambiente \textit{offline}.
\end{itemize}
